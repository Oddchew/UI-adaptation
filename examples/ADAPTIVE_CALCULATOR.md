# Демонстрация адаптации интерфейса калькулятора через SC

Этот сценарий показывает реальную адаптацию через Module A → Module B → Module C.
После двух действий кнопки вычисления runtime автоматически показывает скрытую
дополнительную панель. Решение принимает Module B по событиям, а Module C меняет
свойство `visible` в SC-модели и ждёт подтверждения от браузера.

## 1. Установите расширение калькулятора

В репозитории уже есть базовый интерфейс `ex_calculator`. Файл
`examples/ex_calculator_adaptive.scs` добавляет к нему отдельную скрытую панель
`ex_calculator_adapt_cmp_7` и связь `nrel_ui_output_target` от кнопки
`ex_calculator_cmp_4`. Исходные компоненты калькулятора и `ex_calendar` не меняются.

Из корня репозитория выполните:

```bash
bash examples/install_adaptive_calculator.sh
```

Скрипт копирует SC-расширение в локальную базу знаний ostis-example-app и запускает
пересборку. Для другого расположения ostis-example-app задайте переменную
`OSTIS_EXAMPLE_APP=/path/to/ostis-example-app`.

Если SC machine уже работала во время пересборки, перезапустите её.

## 2. Запустите runtime

```bash
ADAPTATION_RULES="$PWD/examples/ex_calculator_adaptive.rules.json" \
MODULE_A_USE_SC=1 \
MODULE_C_USE_SC=1 \
PYTHONPATH=. python3 integration/server.py
```

Откройте калькулятор:

```
http://127.0.0.1:8765/?interface_id=ex_calculator&sessionless=1
```

## 3. Покажите адаптацию

1. До действий дополнительная панель скрыта (`visible=false`).
2. Нажмите кнопку `=` два раза. Каждое нажатие отправляет событие
   `successful_action` с `action_id=action_calculate_or_append`.
3. Module A передаёт события в Module B.
4. После второго события правило
   `calculator_show_adaptive_panel_after_two_calculations` достигает порога.
5. Module B выбирает единственную выходную цель кнопки — адаптивную панель.
6. Module C проверяет старое значение `false`, записывает `visible=true` в SC
   и ждёт подтверждения применения в браузере.

Панель появляется без перезагрузки страницы. Это и есть демонстрация адаптации:
изменение состояния UI определяется накопленными событиями и правилом Module B,
а не обработчиком кнопки в JavaScript.

> Примечание: текущий пример демонстрирует адаптацию интерфейса по повторным
> действиям. Он не реализует арифметическое вычисление выражения — кнопка калькулятора
> используется как источник событий для проверки механизма адаптации.

## 4. Диагностика

До нажатий проверьте, что панель присутствует и скрыта:

```bash
curl -s "http://127.0.0.1:8765/api/ui-state?interface_id=ex_calculator" | python3 -m json.tool
```

После второго нажатия у компонента `ex_calculator_adapt_cmp_7` должно стать
`visible=true`. В `/api/health` ожидаются `sc=true` и `sc_c=true`.

Если панель не появляется, проверьте вывод сервера и
`/api/runtime/pending?user_id=user_demo`. Не повторяйте тест вслепую: правило
ожидает исходное значение `visible=false`, поэтому после успешного применения
повторно срабатывать не должно.
