# Модуль C: применение адаптации

Модуль принимает `CommandBtoC` и проверяет идентификаторы, базовую версию, компонент, свойство, ожидаемое значение и ограничения. При успехе он передаёт кандидата в runtime, сохраняет новую активную версию с журналом, возвращает результат B и отправляет исход A. Повтор запроса возвращает сохранённый результат. При ошибке C пытается восстановить предыдущий runtime; если восстановление не подтверждено, изменения в этом контексте блокируются.

## Модель и контекст

Снимок модели содержит `id`, `title`, `components` и `links`. Компонент описан через `id`, `typeId`, `props`, связь — через `kind`, `sourceId`, `targetId`. Эти структуры представляют те же компоненты и свойства, что и SC-модель редактора; права изменения задаются `AdaptationPolicy` отдельно от модели.

Для Python-ассистента политика разрешает `hints_panel.visible` и `history_content.visible`. Заголовок истории и содержимое — отдельные компоненты. Записи истории и код ученика хранятся отдельно. При загрузке старого локального снимка `history_panel.collapsed` преобразуется в обратное значение `history_content.visible`.

Для команды с `session_id` версии и активное состояние изолированы по `interface_id`, `user_id`, `session_id`. Контекст получает исходный снимок при первом обращении. Команды без `session_id` используют общий контекст интерфейса. В демо вкладка создаёт отдельный идентификатор сеанса.

## Версии и исходы

`SQLiteRepository` сохраняет версии, результаты, очередь исходов и незавершённые операции. Если процесс перезапущен во время применения, соответствующий контекст блокируется до административного `restore`. Повторная доставка исхода в A выполняется через `retry_notifications`; `event_id` стабилен и равен `request_id`. В локальном сервере повтор запускается периодически.

`asyncio.Lock` и локальный SQLite не координируют независимые процессы или запись из редактора. Перед подключением нескольких писателей нужен общий механизм сериализации и атомарной фиксации. Локальная история A ограничена настройками хранения; дедупликация исходов в A использует доступную историю.

## Адаптер SC-модели

`ScUiModelAdapter` использует `py-sc-client` и существующие `concept_ui_*`, `nrel_ui_id`, `nrel_ui_has_component`, `nrel_ui_contains`, `nrel_ui_value`. `read_property` и `read_model` не создают ключевые узлы. Неоднозначные или отсутствующие компоненты и свойства вызывают ошибку. `update_property` изменяет содержимое одного найденного SC-link после сравнения старого значения.

Для записи требуется `exclusive_writer=True`, и внешняя система обязана обеспечить единственного писателя на всё время операции. Проверка старого значения и запись SC-link не образуют межпроцессный compare-and-set. `ScModelRuntime` выполняет изменение одного свойства и вызывает предоставленный renderer; renderer обязан подтвердить актуализацию представления. Для пользовательских сеансов `scope_resolver(interface_id, user_id, session_id)` должен возвращать ID уже подготовленной персональной модели в SC, а renderer — поддерживать `user_id` и `session_id`. Без этого SC-runtime по умолчанию отклоняет команды с `session_id`, чтобы не изменить общий интерфейс для всех пользователей. Для локальной однопользовательской демонстрации допускается явный флаг `MODULE_C_ALLOW_SHARED_SESSION_MODEL=1`: он направляет сеансовые запросы в общую SC-модель. Это только диагностический режим, не обеспечивающий изоляцию между вкладками и пользователями. Не включать его в многопользовательском окружении. HTTP-маршруты `/api/runtime/pending` и `/api/runtime/ack` в SC-режиме обслуживаются браузерным renderer, который подтверждает фактическое применение интерфейса.

```python
adapter = ScUiModelAdapter('ws://127.0.0.1:8090/ws_json')
await adapter.connect()
snapshot = await adapter.read_model('interface_id')
```

Запись и подтверждение экранного представления необходимо подключать с учётом координации редактора и runtime. Схема терминов версий и исходов находится в `sc/module_c_adaptation.scs`.

## Запуск локального демо

```text
python integration/server.py
```

Открыть `http://127.0.0.1:8765`. Две одинаковые смоделированные ошибки показывают подсказку. После скрытия повторный показ блокируется до конца сеанса. Путь к локальной базе задаётся переменной `MODULE_C_DB`.

Локальные проверки: `python -m unittest discover -s tests -p test_module_c.py -v` и `python -m unittest discover -s tests -p test_runtime_http.py -v`.
